# Security policy

Terran's source is public at <https://github.com/sean35mm/terran>. The latest released minor version receives security fixes; users should update to the newest patch in that minor line.

Terran's boundary excludes a malicious process running as the same user. Skills are managed directory copies with normalized modes and tree-hash drift checks: a catalog edit reaches a destination only through a reviewed `terran plan` and `terran apply`, and skill sources must be world-readable so a copy never widens a private file's permissions. Legacy 0.3 skill symlinks convert to managed copies on the first apply. Global instructions are fixed-destination managed copies with exact-hash drift checks and private adoption backups. Terran protects against accidental collision, path substitution, and drift and rejects repositories, sources, targets, backups, and lock metadata outside the documented local-user ownership and mode boundary.

Terran executes two external programs, always with a fixed argument vector and never through a shell. `git -C <catalog> rev-parse HEAD` is read-only and only reports short commits. For fleet status Terran runs `ssh -o BatchMode=yes -o ConnectTimeout=5 <alias> .local/bin/terran status ...`, and the remote command is only `status` with `--summary --json` or `--local --json`. SSH aliases come from the overlay's `command-centers.json` and are validated against `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` before use; nothing else is passed to `ssh`. Remote output is capped at 1 MiB and strictly decoded. Fleet summaries contain only names, counts, versions, and commits, never file contents. `terran status <name>` is read-only; it strictly decodes the remote's item-level status (which includes that machine's paths) or JSON error and re-encodes it, rejecting any other output as `incompatible terran`. Git runs with a 5-second timeout.

Recommendation: limit Tailscale ACLs (or equivalent network rules) so that only the user's own devices can reach each other's SSH. Anyone who can log in to a Command Center as the user can already run Terran there; Terran does not add authentication of its own. Terran never prompts, so an agent's decisions come only from explicit flags (`--decide`, `--expect`) that the user approved.

Report suspected vulnerabilities with GitHub's **Private vulnerability reporting** feature on the repository Security tab. If that feature is unavailable, open a GitHub issue containing only a non-sensitive summary and request a private reporting channel. Do not include exploit details, credentials, private paths, or other sensitive data in a public issue.

For ordinary non-sensitive bugs, open a GitHub issue with the Terran version, operating system, minimal reproduction, and redacted output.
