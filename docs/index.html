Project a trusted local catalog. See every change first.

Terran is a dependency-free Go CLI that places curated skills, global instructions, and OpenCode configuration at fixed harness destinations. It plans before changing anything, blocks unsafe collisions and drift, and records what it owns.

Install

Use an exact release, inspect the installer, and verify the published checksum before installing.

less install.sh
sh install.sh v0.2.0
terran

Running bare terran in a human terminal guides catalog enrollment, plan review, apply, and verification. Enrollment trusts one user-chosen local catalog; Terran does not search, clone, or fetch one.

For a source build, use Go 1.24 or newer from an exact reviewed commit and run the repository tests first. Release checksums detect corruption or mismatch, but do not replace source and publisher review.

Workflow

  1. Enroll. Inspect and trust one local catalog repository.
  2. Plan. Review every source, fixed destination, action, and reason.
  3. Apply. Terran holds its lock, asks for confirmation of the exact plan, revalidates, then performs eligible work.
  4. Verify. Terran writes a private receipt; use status and doctor to inspect managed state and wider installation health.

The default catalog manages 12 skill projections, two complete global instruction copies, and one OpenCode configuration copy. Skills remain live links to the enrolled checkout. Copied files change only through terran apply.

Advanced and noninteractive use

Bare non-TTY use prints help and never mutates. Deterministic commands and JSON output are available for advanced use:

terran enroll --repo PATH --name NAME
terran plan --json
terran apply --json
terran status --json
terran doctor --json

Collisions and drift

Terran never clears unrelated content to make a plan clean.

missing
Create after review and confirmation.
exact safe file
Adopt it without changing the active file and retain a validated private backup.
safe differing instruction or config
Interactive apply offers replace with backup, keep it unowned, or quit. Empty input and EOF quit.
unsafe collision or receipt-owned drift
Stop. Skills, unsafe file types or metadata, changed managed content, and changed backups are not overwritten.

doctor validates the full receipt, active managed inventory, and every adoption backup. Terran validates ownership, modes, links, boundaries, hashes, and fixed targets; it does not manage secrets, install other tools, or sandbox a malicious process running as the same user.
